# Operator population polling

TreeStats can poll an operator-maintained JSON population snapshot. Registration is maintainer-reviewed and disabled by default. Do not edit autogenerated `data/servers.rb` for this feature.

## Add or disable a feed

Maintainers verify server ownership and endpoint ownership, then add a canonical TreeStats server name and exact HTTPS URL to `config/population_feeds.yml`:

```yaml
feeds:
  Example Server: https://status.example.net/population.json
```

The shipped configuration has `feeds: {}`. A feed can be disabled by removing its mapping; existing `player_counts` history remains. No working Hollowtide endpoint has been confirmed, so do not add or enable the previously suggested URL without revalidation.

## Endpoint contract

TreeStats sends an HTTPS GET every 15 minutes. The response must be a JSON object with:

```json
{"count": 42, "updated_at": 1760000000}
```

- `count` is a nonnegative integer counting connected, in-world player characters, including bots, multiboxed characters, staff, and test characters. Do not count unique people/accounts or exclude operator-defined categories. A measured empty world is `0`; inability to measure must be an error, not a fabricated zero.
- `updated_at` is the integer Unix timestamp in UTC seconds when the population was measured/refreshed, not when the document was served. Advance it for a new measurement even if the count did not change. Re-serving an old snapshot must not renew it.
- Other JSON fields are ignored. TreeStats binds the server identity from reviewed configuration; do not rely on identity or provenance fields in the document.
- Keep the game/exporter clock synchronized. A measurement timestamp must not exceed response receipt time. Old but previously unaccepted measurements can be accepted; there is no age cutoff.

TreeStats accepts only a timestamp strictly newer than that feed's last durably accepted polled timestamp. Duplicates, conflicts at the same timestamp, regressions, malformed documents, future timestamps, HTTP failures, and unsafe destinations do not create population records or refresh displayed data. Failures are logged and summarized in one mutable internal state record; no public polling health indicator is exposed. Polling adds observations alongside Decal plugin reports; neither source suppresses the other.

Transport safeguards include certificate verification, no redirects, DNS resolution/pinning, rejecting private/reserved destinations, response-size limits, and bounded request timeouts. There are no automatic retries or missed-slot backfills. Sidekiq preserves the dispatcher's original enqueue slot; old dispatchers and old queued per-server jobs are skipped, and durable per-server state allows at most one attempt per 15-minute slot.

The per-server lease is 120 seconds, longer than the worker's 90-second hard execution bound. The worker verifies unexpired ownership before starting and immediately before inserting; state writes/releases are qualified by the owner token, and the cursor advances monotonically. MongoDB standalone has no multi-document transaction: if a process is arbitrarily paused in the tiny interval after its last ownership check and before its observation insert, this is not a strict linearizable distributed lock. The unique partial index prevents duplicate polled `(server, measurement time)` records, and the next poll reconciles its cursor against durable polled observations before accepting data, preventing crash recovery from accepting an intermediate older timestamp.

## Local validation and manual test

Prerequisites and service versions are in [setup.md](setup.md). With a local MongoDB 7 and Redis 7, run:

```sh
bundle exec rake test
```

The poller unit/integration tests inject a transport stub, so tests do not need DNS or a real public endpoint and production SSRF checks are not relaxed. For an end-to-end check, configure a temporary, maintainer-controlled HTTPS feed URL, start local MongoDB 7 and Redis 7, then run the worker directly (no Rails/Sinatra console exists):

```sh
bundle exec ruby -r ./lib/sidekiq_boot -e 'PollPopulationJob.new.perform("Example Server")'
```

To test dispatcher enqueueing as well, run `bundle exec ruby -r ./lib/sidekiq_boot -e 'DispatchPopulationPollsJob.new.perform(PopulationPoller.current_slot)'` and have the local Sidekiq process running. Confirm a new `source: "server"` Mongo record has `c_at` equal to the endpoint's `updated_at` and a separate `received_at`; then serve the same timestamp and confirm no duplicate observation. Test an older timestamp, conflicting same timestamp, future timestamp, malformed JSON, HTTP non-200, and measured zero. Remove the mapping afterward. Do not test against production services.

Polling runs every quarter-hour in Sidekiq. There is no public status endpoint; inspect Sidekiq/application logs and the internal `population_poll_states` collection for operations.
